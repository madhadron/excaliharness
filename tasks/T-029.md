# T-029: `make parse` checks task files without spending tokens

* status: draft

## Description
Add `make parse`, which runs Excaliharness's own parser and status rules over `tasks/`, `TASKS.md` and `agents/` and prints a short report, so Claude sessions and agents can check task files by running one command instead of reading and reasoning about them.

## Context
[[docs/task-format]], [[docs/decisions]] D-020 (commands live in the README's Quick reference), D-030, D-034, D-038, D-078. The parser is `src/worker/tasks/parse.ts`, the rules `src/worker/tasks/transitions.ts`, the index `src/worker/tasks/index.ts`, agent files `src/worker/agents/agentDefs.ts`. CLAUDE.md: a command run by hand more than twice becomes a script or Make target. This session bundled a throwaway check script into `dist/check/` by hand five times to do exactly this.

## Issue
Checking that new or edited task files are valid means reading them or writing a one-off script, which costs tokens each time and can miss what the real parser would report.

## Expectation
`make parse` runs in the dev container, using the real modules, and prints for each problem the file, line and message; a summary line (tasks parsed, failures, diagnostics); whether the `## Index` matches what the orchestrator would generate; and each pipeline's agents, checked against `agents/*.md`. It exits non-zero on any error, so it can be a required gate. `make parse ARGS=--json` gives the same as JSON for agents. It's in the README's Quick reference, and has a test. The same tool ships in the base agent image as `excaliharness parse`, so agents on any repository can check its task files; the derived images (`src/worker/runner/images.ts`, D-064) copy it from the base image as they do `claude`, and the capability check confirms it runs.
