# T-001: Open-review link and URI handler

* status: needs-human

## Description
When a task enters `review`, add an "Open review" link to its metadata and an "Open review" CodeLens, both opening the task's review in VS Code.

## Context
[[docs/decisions]] D-014, D-023, D-027, D-041, D-077, D-084. The worktree lives in the extension's storage (D-079). Opening it must not run its `.vscode` tasks or apply its workspace settings (roadmap: security).

## Issue
Today the only way in is the notification's "Open review" button, which opens the worktree folder in a new window.

## Expectation
`* review: [Open review](vscode://madhadron.excaliharness/review/T-NNN)` is added on `review`. A URI handler opens the worktree untrusted, with the diff against the main checkout's branch. The CodeLens appears above the status line and on the task's `TASKS.md` entry.

## Questions
* [X] Q: How should "Open review" show the diff, given the worktree must open untrusted? Our extension declares `untrustedWorkspaces.supported: false` (package.json), so it can't run in the new untrusted window that `vscode.openFolder` opens on the worktree, and nothing there can open the diff. Option A (recommended): change the extension to `untrustedWorkspaces.supported: "limited"`. In an untrusted window it starts no worker, no watcher and no commands. Its only job there is to check whether that window's folder is a review worktree the trusted window just asked to open (handed over through `context.globalState` with the task id, worktree path and a folder of base-file copies), and if so open VS Code's multi-file diff editor (`vscode.changes`). The left side of that diff is the worker's export of the merge-base commit (the human's own commit, made with `exportCommit`-style host git on the main repository). The right side is the live worktree files, which the human can edit directly. Option B: keep `supported: false`. The URI handler opens the same multi-file diff in the current, trusted window, with the worktree files opened as plain files outside the workspace, so the worktree's `.vscode` settings and tasks never apply. The worktree folder is not opened as a workspace folder, which departs from D-014's "opens as a workspace folder". Which should I implement?
  A: limited
