# T-010: Agents pane, activity log and status bar

* status: draft

## Description
A view of what running agents are doing: an Agents pane with one row per running agent or phase, a plain-text activity log per agent, and a status bar summary.

## Context
[[docs/roadmap]] (Agents pane), D-023, D-041, D-067 (the Agent SDK runs in the worker, so every agent's message stream passes through it), D-079 (turn and time limits), D-081. The stream has assistant text, tool calls with their arguments, and turns, tokens and cost in the result; today `src/worker/runner/session.ts` keeps only the session ID, summary and errors.

## Issue
The only view of a running task is the worker's log, which shows little of what the agent is doing.

## Expectation
The worker sends a throttled progress notification for each running task (at most a few per second). The Agents pane shows a row per running agent or phase: the task as a link, the role, the round and phase (e.g. "T-007 · round 2 · reviewing"), the current tool and a short form of its argument ("Bash: `npm test`"), turns used of 100, minutes of 60, and tokens and cost so far. Non-agent phases get rows too ("building image", "gate `make test`", "waiting for approval"). Clicking a row opens that agent's activity log: its messages, tool calls and shortened results, and gate output as it streams, as plain text (an Output channel or read-only document, never a webview), since agent text is untrusted. Tool results that print environment variables are left out. A status bar item reads e.g. "2 agents · T-001 implementing · T-007 gates" and opens the pane.
