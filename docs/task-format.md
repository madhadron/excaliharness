# Task file format

Reference for the files the orchestrator reads and writes. The decisions behind
it are in [decisions.md](decisions.md) (D-005, D-009, D-011, D-030 to D-047).

## Task files: `tasks/T-NNN.md`

```markdown
# T-007: Password reset flow

* status: draft
* depends_on: [[T-001]], [[T-004]]
* pipeline: ui
* kind: infrastructure

## Description
## Context
## Issue
## Expectation
## Questions
* [ ] Q: Should reset links expire?

      A:
## Updates
* 2026-10-23 14:02 · human · status: draft → ready
* 2026-10-23 14:02 · orchestrator · status: ready → waiting-for-dependencies · waiting on [[T-004]]
```

- **Title**: the first line, `# T-NNN: Title`. The id must match the file name.
- **Metadata**: a list of `* key: value` items right after the title. Unknown
  keys are kept and ignored. Known keys:
    - `status` (required): one of `draft`, `waiting-for-dependencies`, `ready`,
      `in-ui-development`, `in-implementation`, `review`, `done`,
      `needs-decision`, `needs-human`.
    - `depends_on`: wikilinks to other tasks, comma separated.
    - `pipeline`: a pipeline name from `TASKS.md`.
    - `kind`: `infrastructure` marks a task every other task waits on.
    - `design`, `review`: links, written by the orchestrator in later features.
- **Sections**: `## Description`, `## Context`, `## Issue`, `## Expectation`,
  `## Questions`, `## Updates`; names are case-sensitive. Headings, questions
  and Updates lines inside fenced code blocks and HTML comments are ignored,
  and a code block or comment that is never closed makes the file invalid.
- **Questions**: `* [ ] Q: question`, then an indented `A:` line for the
  answer; further indented lines continue it. Checking the box (`[x]`) marks it
  answered.
- **Updates**: one line per event, `* <date> <time> · <who> · <text>`. The
  orchestrator only appends. Status changes are written as
  `status: <from> → <to>`, optionally followed by ` · <reason>`. The last such
  line is the task's recorded status: a `status:` line that differs from it was
  changed by hand.

## Status changes

- **You** set `ready` (from `draft` or `needs-human`) and `done` (from `review`
  or `needs-human`), with the "Mark ready" and "Mark done" CodeLens above the
  status line, the matching commands, or by editing the line.
- **The orchestrator** sets everything else. A `ready` task whose dependencies
  aren't `done` moves to `waiting-for-dependencies`, and back when they are.
  Every task except an infrastructure task also waits on all infrastructure
  tasks, so an infrastructure task may only depend on other infrastructure
  tasks. A `needs-decision` task returns to its previous status once every
  question is checked.
- A hand edit that isn't allowed is noted in Updates, ending in "parked", and
  left as is; the orchestrator never reverts your edits. A **parked** task gets
  no automatic changes and nothing starts it. It shows as an error in the
  Problems panel and as `· parked (<status>)` in the index, and the CodeLens
  offers "Mark ready" and "Back to draft" (and "Mark done" if it was parked in
  `review`).
- A `ready` task is started by the orchestrator (`in-implementation`), at most
  two at a time by default (setting `excaliharness.maxParallelTasks`). When
  the implementer finishes it goes to `review`; if it can't run, or runs over
  60 minutes or 100 turns, to `needs-human` with the reason in Updates.
  Changing a running task's status by hand stops it and keeps your status.
  If Claude rejects the sign-in, the task stays `in-implementation` and
  resumes after you sign in again.
- An agent works in its task's worktree, kept in the extension's storage
  (not in the repository), on branch `task/T-NNN`. Its changes to `tasks/`,
  `TASKS.md`, `agents/` or `docs/decisions.md` are never committed.
- Task files must be plain files under 1 MB in a plain `tasks/` directory;
  symbolic links are ignored and reported.
- Status changes that arrive through git (checkout, pull, merge, reset) are
  accepted as they are, not noted as hand edits.
- The orchestrator never writes to a file that doesn't parse, and pauses all
  writes during git merges, rebases and other operations holding the index.
  Problems show up in VS Code's Problems panel.

## Index: `TASKS.md`

```markdown
# Tasks

## Pipelines
* default
    * implement: [[agents/implementer]]
    * review: [[agents/test-reviewer]], [[agents/security-reviewer]]

## Index
* [[T-001]] Choose the stack · done
* [[T-007]] Password reset flow · waiting-for-dependencies
```

- **Pipelines**: each top-level item names a pipeline; its indented items are
  `role: [[agents/name]], ...`.
- **Index**: generated by the orchestrator, one line per task file, sorted by
  id. A task file that doesn't parse is listed as `* [[T-NNN]] · does not
  parse`. Edits to this section are replaced; everything else in `TASKS.md` is
  left alone.

## Links

`[[T-NNN]]` opens `tasks/T-NNN.md`; `[[path/name]]` opens `path/name.md` from
the repository root.
